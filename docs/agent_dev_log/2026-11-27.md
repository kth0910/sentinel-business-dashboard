## 세션 1 — 행 수정 창, 증감액 직접 입력, 구분·값 목록 추가식 (10:20 무렵, Claude Code / Opus 5.5)

### 요청
- 표의 행을 누르면 수정 창(모달)이 뜨고, 고객명·구분·제품·순매출·확도·가중치·매출 구분·매출일정을 고칠 수 있게
- 증감액을 넣으면 시스템(본영업 매출 당일 증감액)에 자동 반영되게
- 변동사항 표의 '구분 관리'를 따로 두지 말고, 구분·제품·확도·가중치·매출 구분은 사람이 값을 만들어 고를 수 있게. 화면 용어로 '사용자 지정'은 쓰지 말 것

### 진행 내용
- 서버 `apps/server/src/biz/store.ts`
  - `editSale(date, key, {fields, categoryId, categoryLabel, delta}, uid)`: 칸 여러 개·구분·증감액을 한 트랜잭션에 저장, 변동 재계산은 한 번
  - 새 표 `biz_delta_edit(date, key, delta)`: 직접 넣은 증감액. `changesFor`는 이 값을 delta로 쓰고 계산값은 `autoDelta`로 함께 준다. `dayDelta`(요약 블록·달력)도 이 값으로 합산
  - 새 표 `biz_option(field, value)`: 값 목록. `listOptions(rows)` = 데이터에 있는 값 + 추가한 값. 새 값으로 고치면 자동으로 목록에 들어감, `removeOption`
  - `setOverride`/`clearOverride`를 `writeOverride`/`deleteOverride`로 나눠 재사용
- `@nc/biz` types: `OPTION_FIELDS`(product, probability, weight, revenueType, progress), `OptionItem`
- RPC `bizEditSale`, `bizRemoveOption`, `bizSalesView` 응답에 `options` 추가
- 웹
  - `features/biz/saleEdit.ts`(+테스트): 바뀐 칸만 보내는 저장 규칙, 금액 읽기(`parseAmount`, 증감액은 음수 허용)
  - `features/biz/editDialog.tsx`: 수정 창, 고르거나 입력하는 목록 칸(`Picker`: ↑↓·Enter, 없는 값은 '새로 추가', 추가한 값·구분은 ×로 지움), 표 표시용 `Shown`, 행 클릭 속성 `openRowProps`
  - `changes.block.tsx`: 구분 선택 상자와 '구분 관리' 버튼 제거, 행 클릭 → 수정 창. 직접 넣은 증감액은 점선 밑줄 + 계산값 안내
  - `pipeline.block.tsx`: 같은 방식(고객·제품·공급가·확도·진행사항·영업대표·영업개시일)
  - `table.tsx`: 행 높이를 끈 직후의 클릭은 수정 창을 열지 않게 막음
  - 지움: `editCell.tsx`(칸 바로 고치기), `CategoryManager.tsx`, 관련 CSS
- `docs/demo.md` 5·12번 시연 설명 갱신

### 결정 사항과 이유
- 칸을 바로 고치던 방식은 행 클릭과 겹쳐 버리고 수정 창 하나로 통일. 진행 중 영업 건 표도 같은 동작이어야 헷갈리지 않아 함께 바꿈(채용 현황 표는 사람이 직접 쓰는 표라 그대로)
- 증감액은 칸 수정값(biz_override, 그 날짜부터 계속 적용)과 달리 '그 날짜·그 건' 하나에만 붙는 값이라 별도 표로 둠. 다시 업로드하거나 순매출을 고쳐도 직접 넣은 증감액이 유지되고, '계산값으로'를 눌러야 계산값으로 돌아감
- 값 목록은 데이터에 실제로 있는 값 + 사람이 추가한 값의 합. 데이터에 쓰이는 값은 지울 수 없고(지워도 다시 나타나므로), 추가했지만 지금 안 쓰는 값만 ×가 보임
- 진행사항도 값 목록 칸으로 함(값 종류가 정해져 있고 분류 규칙에 쓰임). 요청에 없던 부분
- 구분 이름 바꾸기는 화면에서 빠짐(서버 RPC는 남음). 필요하면 목록에 이름 바꾸기를 붙이면 됨

### 문제와 해결
- bash heredoc 따옴표 문제로 파이썬 패치가 깨져 스크립트 파일로 실행
- 3002 시연 서버 재시작 시 TaskStop이 sh만 끄고 node가 포트를 잡고 있어 EADDRINUSE → 해당 node 프로세스를 종료하고 다시 띄움
- 창이 화면보다 길면 저장·취소 버튼이 창 밖으로 나감 → 창 안 스크롤 대신 배경이 스크롤되게(목록이 잘리지 않도록)
- 확인은 개발 서버(5173/3001, 개발용 DB)에서 함: 새 구분 추가 + 증감액 -10,000 저장 → 당일 증감액 927,272 → 14,990,000(계산값 -14,072,728 대체) 확인 후 계산값·원래 구분으로 되돌리고 확인용 구분은 ×로 지움

### 남은 일 / 다음 작업

- 시연 DB(3002)에서는 저장을 시험하지 않음(화면 코드만 반영)

### 관련 커밋

## 세션 2 — 구분·제품·매출 구분 값 추가·삭제·편집 (11:00 무렵, Claude Code / Opus 5.5)

### 요청

- (작업 중) 한국어로 말할 것

### 진행 내용
- 서버 `store.ts`
  - 새 표 `biz_value_map(field, from_value, to_value)`: 값 이름 바꾸기·지우기. `snapshotRows`가 받아온 행에 먼저 적용하고(그 위에 직접 수정값), to_value는 늘 최종 이름(연쇄로 바꿔도 한 번에 적용, 원래 이름으로 되돌리면 표에서 빠짐). to_value ''은 지움
  - `renameOption`·`deleteOptionValue`: 직접 수정값(biz_override)과 값 목록(biz_option)도 같이 바꾸고 모든 날짜의 변동을 다시 계산
  - `removeOption`: 제품·매출 구분이면 `deleteOptionValue`로(쓰는 값도 지움)
  - `listOptions`: 값마다 `count`(쓰는 건 수), `editable`, `removable`
  - `saveCategory`: '미분류' 이름 바꾸기, 같은 이름의 구분 거부
- `@nc/biz` types: `MANAGED_OPTION_FIELDS = ['product', 'revenueType']`, `OptionItem` 확장
- RPC `bizRenameOption`
- 웹 `editDialog.tsx`: 목록 항목에 연필(이름 바꾸기, 이름 입력 창은 `askName` 재사용)과 ×(지우기, 쓰는 건 수를 알리고 확인). 구분은 미분류만 버튼 없음. 바꾸거나 지운 값을 보이던 칸도 함께 갱신해 '바뀐 칸'으로 저장되지 않게 함
- `nameDialog.tsx` `askName`에 안내 글·최대 글자 수 인자 추가
- 테스트 `apps/server/test/biz-option-edit.test.ts`(10개)
- `docs/demo.md` 5·12번 갱신

### 결정 사항과 이유
- 노션 선택 항목과 같은 의미로 함: 값 이름을 바꾸거나 지우면 그 값을 쓰는 모든 건에 적용. 행마다 직접 수정값을 만드는 대신 '값 바꿈 표'를 두어, 지난 날짜와 앞으로 받을 데이터(엑셀·API에서 옛 이름이 와도)에 일관되게 적용되고 이름만 바뀐 것이 가짜 변동으로 잡히지 않게 함
- 확도·진행사항은 분류 규칙(확정·하·보류 등)에 쓰여 이름 바꾸기에서 뺌. 가중치는 요청에 없어 그대로(고르기·추가만)
- 이미 있는 이름으로 바꾸면 두 값이 하나로 합쳐짐(노션과 같음)

## 세션 4 — 변동사항 직접 작성, 본영업 매출 실적 직접 입력 (12:00 무렵, Claude Code / Opus 5.5)

### 요청
- 월별 확정 매출·진행 중 영업 건 블록은 기능은 두고 사용자가 직접 블록을 지움(당장 API 연결은 필요 없어 보인다고 함)
- 변동사항을 전부 수동으로 작성할 수 있게, 본영업 매출도 수동으로 바꿀 수 있게

### 진행 내용
- 서버 `store.ts`
  - 새 표 `biz_manual_change`: 직접 적은 변동 행(날짜, 순서, 칸 값 JSON, 구분, 증감액). 키는 `m:<id>`
  - `addManualChange`, `manualChanges`, `allChangesFor`(받아온 변동 다음에 직접 적은 행), `editSale`가 `m:` 키면 직접 적은 행을 고침
  - 새 표 `biz_change_hidden` + `deleteChange`: 직접 적은 행은 지우고, 받아온 변동은 숨김(다시 받아도 숨김). `changesFor`·`dayDelta`에서 제외
  - `dayDelta` = 받아온 변동(직접 넣은 증감액 우선) + 직접 적은 행 증감액. 데이터 없는 날에도 계산(달력도)
  - 새 표 `biz_actual_edit` + `setActual`·`applyActuals`: 실적 직접 입력. 그 날짜부터 같은 기간 끝까지 적용, NULL은 그 날짜부터 계산값
  - 값 이름 바꾸기·구분 삭제가 직접 적은 행에도 적용
- `@nc/biz`: `ACTUAL_PERIODS`, `ActualPeriod`, `Summary.edited`
- RPC `bizAddChange`, `bizDeleteChange`, `bizSetActual`. `bizSalesView`는 `allChangesFor`·`applyActuals`, `bizCalendar`는 모든 날짜 `dayDelta`
- 웹: 변동사항 '+ 행 추가'(빈 수정 창, `create`·`submit`), 수정 창 '행 삭제'(`remove`), 빈 표 안내 문구. 매출 요약 '실적 입력'(`ActualsEditor`)과 카드 '직접 입력' 표시, 당일 증감액은 데이터가 없어도 변동이 있으면 표시. 달력 상세에 데이터 없는 날 증감 표시
- 테스트 `apps/server/test/biz-manual.test.ts`(13개)
- `docs/demo.md` 4·5번 갱신

### 결정 사항과 이유
- 당일 증감액은 직접 입력 칸을 따로 두지 않고 변동사항 증감액의 합으로 유지(앞서 요청한 '증감액 넣으면 자동 반영'과 맞춤). 변동사항을 전부 직접 적을 수 있으니 결과적으로 수동
- 실적은 날마다 다시 넣지 않아도 되게 '그 날짜부터 그 기간 끝까지' 유지. 다음 달이 되면 월 실적만 계산값으로 돌아감
- 받아온 변동의 삭제는 실제 데이터를 지우지 않고 숨김(다시 받아도 숨김)
- 월별 확정 매출·진행 중 영업 건 블록 코드는 그대로 둠(요청대로)
