### 요청
- 현재 `main`이 이전 세션에서 마지막으로 본 `main`과 같은지 확인
- `demo` 브랜치는 버릴 예정이고 기록용으로만 남겨 둠
- `.gitignore`를 고치고, 다시 시작할 것이니 개발 서버 실행(빌드는 하지 말 것)

### 진행 내용
- `git fetch` 후 비교: 로컬 `main` = `origin/main` = `c5ef813`(2026-11-25 마지막 푸시)
- `demo` 브랜치(로컬·원격 모두 `c03a083`, `main`보다 46커밋 앞섬, 마지막 커밋 2026-11-27 14:25): 다른 세션에서 litpage 기반으로 구현을 진행한 브랜치. 사용자 결정으로 폐기 예정, 기록용으로만 보존
- `main` 작업 폴더의 `app/`, `.impeccable/`: `demo`에서 git이 무시하던 파일(`node_modules`, `apps/server/data`, `apps/web/dist`, 검사기 캐시)이 브랜치를 옮긴 뒤 남은 것. 소스 코드는 없음
- `.gitignore` 새로 작성: `demo`의 규칙(엑셀 파일, 실행 데이터, `node_modules`, 웹 빌드 결과, `.impeccable/`) + Python(`.venv`, `__pycache__`, 각종 캐시) + 환경 변수 파일(`.env`, `.env.example`은 예외)

### 결정 사항과 이유
- 업무관리시스템 엑셀(`*.xlsx`, `*.xls`)은 실제 매출 데이터라 저장소에 올리지 않음(`demo` 규칙 유지)
- 새 스택(FastAPI)에 맞춰 Python 관련 무시 규칙을 미리 추가

### 문제와 해결

## 세션 2 — 첫 구현 계획 작성: 기반 구축 (Claude Code, Opus 5.5)

### 요청
- 새로 만들기부터 시작

### 진행 내용
- superpowers `writing-plans` 스킬로 첫 계획 작성: `docs/superpowers/plans/2026-11-27-foundation.md`
- 설계 범위가 여러 하위 시스템(편집 기능, 업무 화면, 데이터 작업, 배포)이라 계획을 나눔. 첫 계획은 "개발 환경 + FastAPI 뼈대 + 로그인 + litpage 화면 연결"
- 이 PC 개발 도구 확인: Node 26.13, pnpm 10.32.1, Python 3.15.2, git 있음 / **uv, PostgreSQL, Docker 없음** → 계획 Task 2에 winget 설치(사용자 동의 후) 포함
- litpage(`f55fead`)를 임시 폴더에 다시 받아 화면↔서버 규격 확인
  - 모든 호출: `POST /api/rpc/{이름}`, JSON 객체 본문, `x-lit-client-id` 헤더, 쿠키 `lit_session`
  - 오류 본문 `{errorId, name, message}`, 이름은 상태 코드별(UnauthorizedError 401 등)
  - 로그인 화면: `checkSignInMethods` → `signInWithEmail`(비밀번호) / 시작 시 `loadAccountData`(401이면 로그인 화면, 워크스페이스 없으면 온보딩 화면)
  - 서버 처리 함수 약 300개
  - 화면 개발 서버(Vite)는 `NC_API` 기본값 3001로 `/api`를 넘김 → 8000으로 바꾸면 FastAPI로 연결됨
- 계획 구성(7개 작업): 1 litpage 0단계 검증(진행 여부 결정) / 2 uv·PostgreSQL 17 설치, 개발·테스트 DB / 3 FastAPI 뼈대·DB 연결 / 4 RPC 처리 틀 / 5 사용자·세션 테이블, argon2, Alembic, 계정 생성 CLI / 6 로그인 RPC / 7 litpage 화면 복사와 개발 서버(API 8000, 화면 5173)
- 계획 완료 시 모습: 관리자가 만든 계정으로 로그인 → 워크스페이스 만들기(온보딩) 화면까지 동작

### 결정 사항과 이유
- 이메일 코드 로그인(litpage 기본 방식)은 지원하지 않고 비밀번호만: 회원가입 없음, 관리자가 계정 발급(설계 8.10)
- 없는 이메일과 틀린 비밀번호에 같은 오류 문구: 계정 존재 여부를 덜 드러내기 위해
- Python 버전은 uv로 3.13 고정: PC의 3.15는 라이브러리 지원이 아직 불확실(미검증)
- 테스트용 DB를 따로 둠(`sentinel_test`)

### 진행 내용
- litpage 언어 구조 확인(`apps/web/src/features/shell/i18n.ts`): 언어는 `en-US`/`ko-KR` 두 개, 기본 `en-US`, `localStorage`의 `nc:locale`로 저장. 화면 문구는 `t('lp.…', '영어 기본값')` 방식이고 한국어 카탈로그 `i18n.ko-KR.json`에 3,878개 키. 코드에서 쓰는 키 3,813개 중 한국어가 없는 키는 0개(정규식 검사 기준). 언어를 바꾸는 곳: 로그인 화면, 설정 › 기본 설정, `userSettings.ts`
- `.gitignore`에 임시 파일 규칙 추가: 커버리지, 테스트 결과, 로그, `*.tmp`, `.vite/`, 운영체제·편집기 파일 등
- `AGENTS.md`에 "커밋하지 않는 파일" 규칙 추가: 임시 파일 커밋 금지, `git add -A`/`git add .` 금지(경로 지정), 커밋 전 `git status` 확인

  - Task 5: 인증 공급자 인터페이스(`AuthProvider`, `Identity`), 로컬 비밀번호 공급자, 외부 공급자용 자동 계정 생성(`provision_external_user`), 사용자 테이블에 `auth_source`·`external_id`, 샘플 계정 3개(`seed-sample-users`, 운영 환경에서는 거부)
