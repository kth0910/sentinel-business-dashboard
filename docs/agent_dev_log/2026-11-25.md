## 세션 1 — 저장소 초기 설정과 에이전트 규칙 작성 (Claude Code, Opus 5.5)

### 요청
- 이 폴더를 원격 저장소 `kth0910/sentinel-business-dashboard`에 연결
- SSH 대신 HTTPS 방식으로 연결
- `AGENTS.md`를 만들어 다음 규칙을 정리
  - `docs/agent_dev_log/`에 모든 개발 대화를 날짜별로 기록 (커밋 내역보다 자세하게, 다른 환경에서도 맥락을 알 수 있도록)
  - 수정 내역이 논리적으로 한 커밋 단위가 되면 커밋을 제안
- 작성한 내용을 한 번 커밋하고 푸시

### 진행 내용
- `git init` 후 `origin`을 `git@github.com:kth0910/sentinel-business-dashboard.git`으로 추가
- SSH 접속 확인이 실패해 `origin`을 `https://github.com/kth0910/sentinel-business-dashboard.git`으로 변경
- `git fetch` 후 로컬 `main`을 `origin/main`에 연결 (`git switch -c main --track origin/main`). 원격의 `README.md`(Initial commit)를 받아옴
- `AGENTS.md` 작성: 개발 기록 규칙(파일 경로, 세션 형식, 작성 원칙)과 커밋 제안 규칙(제안 시점, 포함 내용, 메시지 형식)
- 이 파일(`docs/agent_dev_log/2026-11-25.md`) 작성

### 결정 사항과 이유
- **HTTPS 사용:** 이 PC에는 `~/.ssh` 폴더가 없어 SSH 키와 `known_hosts`가 없음. 키 생성과 GitHub 등록 대신, 이미 설정된 Git Credential Manager(`credential.helper=manager`)를 쓰는 HTTPS를 사용자가 선택함
- **로그 파일 단위:** 하루에 파일 하나(`YYYY-MM-DD.md`), 같은 날 작업은 세션으로 추가. 날짜로 찾기 쉽고 파일 수가 지나치게 늘지 않음
- **커밋 정책:** 에이전트는 커밋을 제안만 하고, 사용자가 승인한 뒤에 커밋·푸시하도록 규칙화
- **파일명:** 여러 에이전트 도구가 인식하는 관례에 맞춰 `AGENTS.md`(대문자)로 작성

### 문제와 해결
- SSH 접속 시 `Host key verification failed` 발생 → 원인은 SSH 키·`known_hosts` 부재. HTTPS로 변경해 해결
- 처음 확인했을 때는 git `user.name`/`user.email`이 없었으나, 커밋 시점에는 전역 설정에 들어가 있어 그대로 사용
